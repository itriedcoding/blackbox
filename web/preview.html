Memory guard on 4 GB

Qwen2.5 0.5B abliterated · 4096 context · CPU only
Why did the app refuse to load a 3B model on my 4 GB laptop?
Because the weights and the KV cache together did not fit. The loader reads the GGUF header, computes the cache size from the layer count, head count and context length, and compares that against the machine's budget. A 3B Q4_K_M needs roughly 2 GB for weights and another half gigabyte for a 4096-token cache, which leaves nothing for Windows.
And if I lower the context to 2048?
It fits with less headroom. Halving the context halves the KV cache, so the estimate drops by about 250 MB. The guard would still warn on a busy machine, but you can override it deliberately instead of discovering the limit through a swap storm.
