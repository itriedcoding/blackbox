Blackbox is a desktop app that runs uncensored, abliterated GGUF models on your CPU. Models come straight from Hugging Face, weights stay on your disk, and every token is generated locally — no account and no cloud round trip.

What it does

Everything stays on the box

No proxy, no telemetry, no hidden system prompt layered over yours.

Real local inference

llama.cpp through node-llama-cpp. Streaming tokens, stop mid-reply, context rebuilt from your transcript. Your CPU does the work.

Models from Hugging Face

Search the Hub, inspect a repo's GGUF files, and download resumably. The app reads each file's GGUF header and refuses models that won't fit in RAM.

RAM guard, not guesswork

KV cache is computed from the model's own header before loading, so a 4 GB machine gets a clear answer instead of a swap storm. The Performance page shows live memory and sizes threads, context window and acceleration to your machine in one click.

Zero guardrails in the path

No moderation layer, no refusal prompt, no server policy. The model answers with its own weights and your system prompt.

Import what you already have

Drop a .gguf into the model folder or add it from disk. Downloaded files are verified against their byte size.

Updates without reinstalling

A button in the sidebar checks GitHub releases, downloads the new build with progress, checks its SHA-256 against the published manifest before running it, then restarts into it. Models, chats and settings stay where they are.

Discord bot on your own model

Add a bot token in Settings and the loaded model answers DMs, mentions and one channel — no hosted API in the path. Rich Presence shows the model you are running, with the Blackbox logo, over Discord's local socket.

Monochrome glass UI

Built with the platform's own widgets and a single accent: none. Keyboard-first composer, honest status line, no decorative noise.

Code

An editor and a shell, driven by the model on your CPU

Open a folder, edit files, run commands, and have the local model write whole files into it. No snippets leave the machine.

Editor

Folder tree, CodeMirror, conflict-aware saves

The explorer skips node_modules, .git, dist and other build folders, and tells you when a tree is too large to list fully. All 156 languages CodeMirror ships a mode for are wired in, and a script loads every mode package to prove it; anything without a mode opens as plain text and is still editable. Folders open from a picker, a typed absolute path, or the recent list.

Saving a file that changed on disk asks before overwriting instead of discarding the change.

Terminal

xterm.js inside the app

A real shell starts in the open folder — cmd.exe on Windows — so npm install, git, node, python and build scripts run exactly as they do outside the app.

It is a pipe-backed session rather than a pty, so full-screen terminal programs that demand a terminal device will complain. Credential-shaped environment variables are stripped from the child process.

Projects written by the model

Build until done runs round after round, handing the model the files it has already written and asking for what is still missing. It stops when the model signals completion, when a round changes nothing, or at the budget — and reports every file it wrote. A plan-only mode lets you review a single reply first. Absolute paths and .. are rejected before anything touches the disk.

What it is honest about

A 1–3B abliterated model writes small projects well and large frameworks poorly, and the context window bounds how much of a repository can be considered at once. There is no language server, so completion is bracket and indent behaviour, not symbol analysis.

No account, no cloud workspace

The editor, the shell and the model all run in the packaged app. There is no remote session, no synced workspace and no telemetry about what you open.

Studio

Three things the app can do beyond chatting

Each one runs on this machine. Nothing is proxied to a service.

Publish

A website that runs the model in the visitor's browser

Export a static site with the wllama runtime and a single GGUF URL. Visitors download the model once and generate on their own CPU. Deploy the folder to Vercel, Netlify or any static host — there is no inference server to pay for.

API

OpenAI-compatible access for your own tools

Start a local server exposing /v1/chat/completions and /v1/models, with bearer keys stored as hashes, streaming responses and per-key rate limits. Point any OpenAI client at it.

Fine-tune

LoRA training on your own data

Feed it JSONL chat data or plain text, provision an isolated CPU PyTorch environment, train an adapter, then merge it and convert to GGUF with llama.cpp's converter so the result loads in the app.

Install

Two ways in

Windows installer

  1. Download Blackbox-1.7.3-win-x64.exe (400 MB) from the release page.
  2. Run it. SmartScreen warns because the build is unsigned — More info → Run anyway.
  3. Open Blackbox, pick a model in Models → Discover, and let it download.
  4. Press Load, then type. No account step exists.

Each installer ships with a Sigstore bundle you can check with cosign (command in the README). That proves the build's origin and integrity — it is not Authenticode, so SmartScreen still warns.
