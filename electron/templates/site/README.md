# __TITLE__

A static chat site generated by Blackbox. The language model runs inside the
visitor's browser with WebAssembly, so there is no inference server, no API key,
and no per-message cost.

## What is in here

| File | Purpose |
| --- | --- |
| `index.html`, `style.css`, `app.js` | The chat interface |
| `engine.js` | Browser inference wrapper around wllama (llama.cpp → WebAssembly) |
| `config.json` | Title, system prompt, model URL and sampling defaults |
| `vendor/wllama/` | The wllama runtime and its WebAssembly binary |
| `vercel.json` | Static hosting config |

## Deploy to Vercel

**Option A — dashboard.** Go to <https://vercel.com/new>, choose *Deploy from
your computer*, and drop this folder in. No build step, no environment variables.

**Option B — CLI.**

```bash
npx vercel login
npx vercel deploy --prod
```

The first run asks which scope to use and creates the project. Every later run
from this folder redeploys the same project.

**Option C — Git.** Commit this folder to a repository, import it in Vercel, and
set the framework preset to *Other* with an empty build command. Output is the
repository root.

## Change the model

Edit `config.json`. `modelUrl` must point at a single-file GGUF (or a repo
`resolve` URL) that the browser can fetch with CORS enabled. Hugging Face
`resolve/main` URLs work.

```json
{
  "modelUrl": "https://huggingface.co/owner/repo/resolve/main/model-Q4_K_M.gguf"
}
```

Visitors download the GGUF once; the browser caches it. Keep the file small
(≤ 1 GB) if you want phones to be able to load it. Any model that fits in the
visitor's RAM works, and the page never sends prompts anywhere.

## Notes

- Everything is static. Vercel only serves files.
- Inference is single-threaded WebAssembly, so it works without cross-origin
  isolation headers. To use multiple threads you would need `COOP`/`COEP`
  headers and a cross-origin-isolated host.
- The model file is fetched from the URL in `config.json`, so that host must
  allow cross-origin reads.
